Use case & requirements

AreaWhat is built
ScopeHome page plus the shared /nav and /footer fragments. The repo's pages.json lists one page (home → https://rjrt.com/).

Harness notes for this site

  • Records vs replay: the MHTML replay reports the overlay text at 18px; the live-captured records (what the gate compares) say 14px. Values were taken from the records.
  • Fragments and icon tokens: build.py converts :icon: tokens only in pages, not in fragment .plain.html files. tools/fragments_local.py applies the same conversion to the local nav/footer copies (the pipeline does it on DA content).
  • Inline &nbsp;: the pipeline serves &nbsp; next to an inline tag as NBSP + space. Content authors a plain space there (tools/gen_content.py).
  • Port: another session's aem up held port 3000, so this repo's local server ran on 3017 (site.json / gate/home.json).
  • Image keys: the gate pairs images by file name. Local media uses the source's rendered renditions (…-1536x864.jpg etc.) so they pair; after DA upload EDS renames content images to media_<hash>, which shows them as unpaired in a post-publish gate (expected, reported, not hidden).
  • Theme images vs content images: the hero overlay PNG, swoop background, logos and SVG shapes are design assets of the theme, so they live in the repo (/images, /icons, inline SVG). The hero photo and the 4 card photos are content and go to DA.

Rules from the repo's AGENTS.md

  • Markup comes from the backend: fetch /path.plain.html before writing a block.
  • buildAutoBlocks rewrites content before a block runs; authors omit and add cells, so decorate defensively.
  • Scope CSS to .blockname; -wrapper and -container are section classes.
  • A PR without a {branch}--rjrt--AdobeDrago.aem.page/{path} link is rejected.
  • Merging main ships code; content is previewed and published separately in DA.
  • All committed files are served — use .hlxignore for anything that should not be.

Authoring workflow in DA.live

  1. Open da.live/#/adobedrago/rjrt and edit the document.
  2. Preview from DA (or use the Sidekick) and check https://main--rjrt--adobedrago.aem.page/.
  3. For a code change, branch from main, push, and open the PR with the <branch>--rjrt--adobedrago.aem.page link.
  4. Publish content to .aem.live after QA.
